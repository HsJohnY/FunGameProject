# ADR-0002：使用 URP、新输入系统与分层测试门禁

- 状态：已接受
- 日期：2026-09-01

## 背景

本项目是 Unity 6 的 3D 第一人称合作游戏，目标画面是清晰、低复杂度的风格化低模表现。项目需要在普通好友电脑上运行，并在玩法迭代期间维持稳定的自动验证入口。

## 候选方案

- Built-in Render Pipeline：初始依赖最少，但新项目的可视化工具、Shader Graph 与后续维护路径较弱。
- Universal Render Pipeline：覆盖目标画面和平台，质量档位明确，复杂度适中。
- High Definition Render Pipeline：高端画质能力更强，但对本项目的硬件目标、素材质量和维护成本不合适。

## 决策

1. 使用 Unity `6000.0.38f1` 和 URP `17.0.3`，渲染资产由项目内编辑器脚本确定性生成。
2. 使用 Input System `1.13.0`，键鼠优先；MVP 前再验证控制器。
3. 运行时代码、编辑器工具、EditMode 测试与 PlayMode 测试使用独立程序集。
4. 纯规则进入 EditMode；场景、物理和 Unity 生命周期进入 PlayMode；玩家可见循环还必须生成 Windows 开发构建。
5. Unity 可执行文件不依赖全局 PATH，由 PowerShell 入口显式定位或接受参数覆盖。

## 后果

- 项目获得适合风格化 3D 的现代渲染基线，后续可使用 Shader Graph 和 URP 渲染功能。
- 首次导入需要解析 URP 包并生成渲染资产，仓库体积和着色器导入时间略有增加。
- 编辑器专用逻辑不会进入玩家构建，测试依赖也不会污染运行时程序集。
- 更换渲染管线属于架构决策，需要新增 ADR，而不是直接覆盖本记录。
