# M4 功能保留审计与双模式构建

基线：M4 `18059eb`，单人 `ad3ac46`，三工具战斗 `0cd4645`。

## 原因

两个分支的最新提交确实都是 M4 的祖先，但这只能证明提交已合并。M4 生成器删除单人玩家、停用单人组件，再生成简化联网玩家、敌人与 HUD；因此代码在仓库中，运行效果却没有接入。此前只用提交祖先关系和启动冒烟判断“最新整合”是不充分的。

| 项目 | 原 M4 问题 | 本次处理 |
|---|---|---|
| 任务导航 | 原导航被停用，只有一行联网章节文字 | 原导航渲染器读取同步状态，恢复操作句、进度、主次目标、距离、背后目标稳定标记 |
| UI | 技术事故 HUD、会话、章节、聊天分别绘制，菜单也被覆盖 | 统一任务栏，隐藏普通玩法中的技术事故 HUD，聊天与导航错开，菜单打开时隐藏联网 HUD |
| 工具腰带 | 联网玩家未配置 | 恢复三工具用途、装备状态与联网手持管件显示 |
| 手持模型 | 联网生成器使用圆柱和方块 | 调用原精细工具生成器，并明确限定目标玩家，避免改错场景对象 |
| 工具反馈 | 联网玩家没有原反馈组件 | 恢复挥击、喷枪后坐、桥接器脉冲、音效与本地镜头反馈；不对联机全局时间做顿帧 |
| 压力表/泵体 | 旧接口虽 disabled，射线选择仍调用；泵代理仍指向单人诊断 | 跳过停用接口，泵壳代理改接联网站点，并以真实准星/E 验证 |
| 敌人差异 | 同形胶囊敌人，工具多数只扣血 | 增加虫群、侧袭、护盾精英、远程体外形差异；恢复喷枪范围伤害/减速、桥接瘫痪/破盾、扳手击退 |
| 章节表现 | 章节灯光和机械动画一并冻结 | 展示组件读取同步章节；任务逻辑仍由服务器控制 |
| 单人入口 | 构建仅包含 M4 联机场景 | 同一 EXE 的主菜单提供单人/联机入口；单人直接使用原完整三章场景，可返回模式选择 |
| 构建来源 | 单人场景存在时不重建，可能遗留旧工具模型 | 双模式构建先重建单人场景，再生成 M4；两场景均写入构建清单 |

## 首轮恢复验证（2bbab35）

- EditMode 79/79，PlayMode 38/38。
- M4 集成测试通过真实准星选择、交互执行、主机 RPC 验证压力表和泵体。
- 验证三个精细手持模型、导航组件、联网工具腰带和单人场景在构建配置内。
- 验证虫群数量、喷枪多目标伤害与减速、精英对扳手的护盾免伤、桥接器破盾和瘫痪。
- 完成主机冷却、继电器和三波核心防卫测试。
- 开发参数 `--m4-check-output=<绝对目录>` 用实际 EXE 检查主菜单、联网导航/工具模型、单人入口、设置页和返回菜单，并保存截图。
- 播放器检查发现并修复了跨场景残留的网络管理对象；切到单人前等待网络关闭并销毁持久化会话对象。
- 检查截图发现两个功能分支叠加后单人工具腰带与导航占据同一位置；现在单人与联机均将工具腰带放在右侧。
- 最终实际 EXE 检查退出码 0，日志确认 `[M4BuildCheck] PASS`。已查看主菜单、单人导航与设置页截图，未再出现菜单黑屏或导航/腰带重叠。

## 共享地图与交战空间（2026-09-04）

- 单人与联机从同一个三章地图生成器构建。新增回归检查逐项比较场景模型、世界位置、朝向、比例，以及每个干扰体的出生点和接近路径。
- 干扰体改在设备前方的开阔区域交战。生成时避开设备、栏杆和墙体，预留 1.25 米设备间隔，并分配独立交战位置；侧袭路线也从相同地图数据读取。
- 修正父舱室平移后仍保存旧世界出生坐标的问题，防止第二、三章敌人在遭遇开始或重置时回到第一章。
- 联机不再另设虚拟防卫目标和密集出生阵列，改为读取原地图的冷却遭遇、继电器遭遇和五波风暴防卫；共用敌人血量、速度、攻击间隔、蓄力规则、外形、扳手伤害和击退距离。
- 两种模式均保留冷却两支路、冷却战斗干扰升温、五波防卫，以及失败后到本舱恢复终端重启章节。网络敌人的蓄力连线与状态通过服务器同步。
- 批处理测试和带检查参数的 EXE 自动静音，不写入玩家的正常音量设置。

验证结果：EditMode **80/80**，PlayMode **39/39**。实际运行检查覆盖出生点重置、设备间隔、准星射线命中、接近位置可达、主机两支路/五波流程，以及通过真实 E 交互重启失败章节。实际 EXE 双模式检查退出码为 0，并已查看两种模式的战斗截图。

截图：[联机交战空间](Captures/M4-SharedMap/07-coop-combat.png)、[单人交战空间](Captures/M4-SharedMap/08-solo-combat.png)。

## 单人场景作为唯一运行地图

此前的“共享地图”只表示共用生成器，仍打包了两份场景副本。本轮改为只构建 `SinglePlayer_ThreeChapterDemo.unity`，删除旧 `M4_CoopThreeChapterDemo.unity` 副本。`SharedMapModeController` 在地图对象初始化前选择本地或联网控制器；单人与联机的主菜单、重启、返回菜单均加载同一个场景。地图内容以单人版本为准。

- 第二章桥接器架与扳手架移至入口旁，避开第二座继电器及其交互范围。
- 325 铭牌文字改为面向通道，缩小字号以完整放进铭牌；已检查实际 EXE 截图。
- 第三章补齐桥接器与喷枪工具架，避免应对护盾精英时必须返回前舱。
- 波次组合改为逐步增加总生命与战术要求；第三章敌人攻击间隔延长 40%，单次设备伤害降低约 35%。第二、三章扳手采用 2 点重击伤害。

| 波次 | 主题 | 敌人组合 |
|---|---|---|
| 1 | 基础拦截 | 2 直行 + 1 侧袭 |
| 2 | 侧翼突袭 | 2 直行 + 2 侧袭 |
| 3 | 远程支援 | 2 直行 + 2 侧袭 + 1 脉冲 |
| 4 | 破盾与护送 | 2 侧袭 + 2 脉冲 + 1 护盾精英 |
| 5 | 混合总攻 | 2 直行 + 2 侧袭 + 1 脉冲 + 1 护盾精英 |

每波先准备 4 秒。第一波全员随后入场，其他波次分成两批，于第 4 秒和第 8 秒入场；护盾精英随第二批到达。未入场敌人无显示、无碰撞、不能造成伤害或被提前击杀，但计入波次剩余人数。界面显示下一批倒计时，清场后仍需手动确认下一波。单人与联机读取同一组编排数据。

最终验证：EditMode **81/81**、PlayMode **40/40**。实际 EXE 已确认构建场景数量为 1，并完成主机启动、单人切换、设置页、返回菜单，以及铭牌和工具架截图验证。新增测试覆盖单人第 4/8 秒分批入场、联网五波通关、工具架与继电器间距、第三章三工具补给与护盾精英延迟入场。全部自动检查静音。旧攻击测试改为限时等待设备离线，避免固定 120 毫秒造成的帧率误报。

截图：[325 正向铭牌](Captures/Canonical-Solo-Map/09-plate-325.png)、[工具架与继电器分离](Captures/Canonical-Solo-Map/10-relay-rack-clearance.png)。

## 保留的模式差异与验证范围

- 联机通过服务器推进任务、生成敌人和共享搬运物品；单人为本地运行。单人暂停会冻结世界，联机打开菜单不会暂停其他玩家。
- 联机仍未同步逐章计时及 325 铭牌的全队发现记录；两种模式的章节 HUD 文案与布局仍有差异。
- 目前验证包含主机集成测试和实际 EXE 双模式检查，尚未进行两名真人完整联机通关或约半小时真人试玩。

## 构建

Unity 6000.0.82f1；Windows x64 Development Build。

调用 `Tools/Build-M4.ps1`，输出 `Builds/M4-Coop-Windows/FunGame-M4-Coop.exe`。分享时保留整个构建目录。
