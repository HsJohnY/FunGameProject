# M4 功能保留审计与双模式构建

基线：M4 `18059eb`，单人 `ad3ac46`，三工具战斗 `0cd4645`。

## 原因

两个分支的最新提交确实都是 M4 的祖先，但这只能证明提交已合并。M4 生成器删除单人玩家、停用单人组件，再生成简化联网玩家、敌人与 HUD；因此代码在仓库中，运行效果却没有接入。此前只用提交祖先关系和启动冒烟判断“最新整合”是不充分的。

| 项目 | 原 M4 问题 | 本次处理 |
|---|---|---|
| 任务导航 | 原导航被停用，只有一行联网章节文字 | 原导航渲染器读取同步状态，恢复操作句、进度、主次目标、距离、背后目标稳定标记 |
| UI | 技术事故 HUD、会话、章节、聊天分别绘制，菜单也被覆盖 | 统一任务栏，隐藏普通玩法中的技术事故 HUD，聊天与导航错开，菜单打开时隐藏联网 HUD |
| 工具腰带 | 联网玩家未配置 | 恢复三工具用途、装备状态与联网手持管件显示 |
| 手持模型 | 联网生成器使用圆柱和方块 | 调用原精细工具生成器，并明确限定目标玩家，避免改错场景对象 |
| 工具反馈 | 联网玩家没有原反馈组件 | 恢复挥击、喷枪后坐、桥接器脉冲、音效与本地镜头反馈；不对联机全局时间做顿帧 |
| 压力表/泵体 | 旧接口虽 disabled，射线选择仍调用；泵代理仍指向单人诊断 | 跳过停用接口，泵壳代理改接联网站点，并以真实准星/E 验证 |
| 敌人差异 | 同形胶囊敌人，工具多数只扣血 | 增加虫群、侧袭、护盾精英、远程体外形差异；恢复喷枪范围伤害/减速、桥接瘫痪/破盾、扳手击退 |
| 章节表现 | 章节灯光和机械动画一并冻结 | 展示组件读取同步章节；任务逻辑仍由服务器控制 |
| 单人入口 | 构建仅包含 M4 联机场景 | 同一 EXE 的主菜单提供单人/联机入口；单人直接使用原完整三章场景，可返回模式选择 |
| 构建来源 | 单人场景存在时不重建，可能遗留旧工具模型 | 双模式构建先重建单人场景，再生成 M4；两场景均写入构建清单 |

## 实际验证

- EditMode 79/79，PlayMode 38/38。
- M4 集成测试通过真实准星选择、交互执行、主机 RPC 验证压力表和泵体。
- 验证三个精细手持模型、导航组件、联网工具腰带和单人场景在构建配置内。
- 验证虫群数量、喷枪多目标伤害与减速、精英对扳手的护盾免伤、桥接器破盾和瘫痪。
- 完成主机冷却、继电器和三波核心防卫测试。
- 开发参数 `--m4-check-output=<绝对目录>` 用实际 EXE 检查主菜单、联网导航/工具模型、单人入口、设置页和返回菜单，并保存截图。
- 播放器检查发现并修复了跨场景残留的网络管理对象；切到单人前等待网络关闭并销毁持久化会话对象。
- 检查截图发现两个功能分支叠加后单人工具腰带与导航占据同一位置；现在单人与联机均将工具腰带放在右侧。
- 最终实际 EXE 检查退出码 0，日志确认 `[M4BuildCheck] PASS`。已查看主菜单、单人导航与设置页截图，未再出现菜单黑屏或导航/腰带重叠。

截图：[模式主菜单](Captures/M4-Restored/01-mode-menu.png)、[联网导航](Captures/M4-Restored/02-coop-guidance-wrench.png)、[单人导航](Captures/M4-Restored/05-solo-guidance.png)、[设置页](Captures/M4-Restored/06-solo-settings.png)。

## 尚不能声称完全等价的内容

- 单人仍保留原五波核心防卫、章节内恢复终端、冷却维修战斗中断、章节计时和 325 彩蛋。
- 联机战役仍是三波核心防卫及自动战斗重置；未把完整单人节奏、第一章战斗中断和逐章计时全部移植到联网规则。
- 联机铭牌保留本地发现表现，不同步全队发现状态。
- 本次主机集成与双模式播放器检查不等于两名真人完整联机通关，也不等于约半小时真人试玩。

## 构建

Unity 6000.0.82f1；Windows x64 Development Build。

调用 `Tools/Build-M4.ps1`，输出 `Builds/M4-Coop-Windows/FunGame-M4-Coop.exe`。分享时保留整个构建目录。
