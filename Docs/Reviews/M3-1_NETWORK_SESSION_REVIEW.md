# M3-1 网络会话人工评审

状态：已通过（2026-09-02）

## 已修复问题

### M3-1-ISSUE-01：连接不可达地址后界面锁死

- 现象：客户端输入 `127.0.0.3` 等当前没有主机监听的合法 IPv4 后，连接失败但地址输入持续禁用；主机侧也出现无法可靠主动停止的情况；
- 原因：初版界面直接使用 NGO 的异步 `IsListening` 作为输入与停止按钮状态，失败后又没有主动清理传输会话；Unity Transport 默认还可能重试约一分钟；
- 修复：引入显式会话状态，连接重试限制为约 3 秒，断开回调后延迟一帧安全清理，并让停止按钮独立于 `IsListening`；
- 状态：自动回归及人工复测通过。

### M3-1-ISSUE-02：主机端口被占用后界面锁死

- 现象：已有主机或其他程序占用 `7777` 等端口时，新主机再次使用该端口会启动失败并停留在不可操作状态；
- 原因：端口绑定失败由 Unity Transport 通过 `OnTransportFailure` 报告，初版控制器没有订阅该事件；
- 修复：启动 NGO 前先检查本机 UDP 端口；已占用时不进入 Unity Transport，直接恢复输入并提示玩家更换端口；`OnTransportFailure` 继续处理检查与实际绑定之间的极小概率竞争；
- 自动验证：PlayMode 测试会独占一个系统随机分配的 UDP 端口，确认主机被启动前检查拦截、NGO 未进入监听状态且没有底层绑定红色错误；
- 状态：自动回归及人工复测通过。

## 本阶段验证范围

本阶段只验证两份游戏实例能通过 IPv4 地址和端口建立监听主机会话，并能正常断开、停止和再次连接。玩家生成、移动、工具、任务物和事故状态尚未联网，它们分别属于 M3-2 至 M3-4。

当前界面是开发验证面板，不代表正式大厅或好友邀请界面。M3 暂不接入 Relay、邀请码、公开匹配或 Steam。

## 场景与操作

1. 使用 Unity `6000.0.38f1` 打开项目；
2. 双击 `Assets/Game/Scenes/M3_NetworkSlice.unity`；
3. 准备两个可同时运行的实例（Multiplayer Play Mode 的 Player 2，或后续生成的开发构建）；
4. 两个实例都保留地址 `127.0.0.1`、端口 `7777`；
5. 实例 A 点击“启动主机”；
6. 实例 B 点击“加入主机”；
7. 观察双方状态和主机的连接人数；
8. 在客户端点击“停止 / 断开”，然后再次加入；
9. 在主机点击“停止 / 断开”，确认客户端收到断开反馈。

局域网跨设备测试时，客户端地址应改为主机设备的局域网 IPv4；主机仍使用同一端口。Windows 防火墙若首次询问，只需允许专用网络。

## 检查清单

- [ ] 未启动时可以编辑 IPv4 地址和端口；
- [ ] 主机启动后显示“主机已启动”或玩家连接消息；
- [ ] 客户端成功连接后显示“已连接到主机”；
- [ ] 主机连接人数由 1 变为 2；
- [ ] 会话运行时不能重复点击启动主机或加入主机；
- [ ] 客户端主动断开后可以再次加入；
- [ ] 主机停止后客户端收到断开反馈，不会卡死或残留会话；
- [ ] 输入空地址、`localhost`、端口 `0` 或大于 `65535` 时显示可读错误；
- [ ] 输入当前无人监听的合法地址（如本机测试中的 `127.0.0.3`）时，约 3 秒内失败并恢复输入；
- [ ] 客户端处于“正在连接”时仍可主动点击“停止 / 断开”；
- [ ] 两个主机使用同一端口时，第二个主机显示端口占用提示并恢复输入；
- [ ] 第二个主机更换到未占用端口后可以重新启动，不需要退出 Play Mode；
- [ ] Console 没有进入 `Assets/Game` 调用栈的红色错误。
