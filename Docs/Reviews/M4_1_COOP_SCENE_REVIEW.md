# M4-1 多人三舱场景评审

## 本阶段实现

- 从已验收的三章单人场景生成独立 `M4_CoopThreeChapterDemo`，不修改原验证场景。
- 移除场景内本地玩家，统一由 `NetworkManager` 按所有权生成联网玩家。
- 保留三舱模型、章节门和静态碰撞；事故、任务物和敌人逻辑暂时冻结，等待 M4-2/M4-3 主机权威改造。
- 接入直接 IPv4/端口会话、玩家颜色与位置同步、F1 会话面板、F2 网络诊断和 F3 文字聊天。
- 提供独立 Windows Development Build。

## 人工核验

1. 用 Unity 打开 `Assets/Game/Scenes/M4_CoopThreeChapterDemo.unity`，确认 Console 无编译错误。
2. 启动编辑器实例作为主机，再启动 `Builds/M4-Coop-Windows/FunGame-M4-Coop.exe` 作为客户端。
3. 客户端通过 `127.0.0.1:7777` 加入；确认双方出生在冷却舱内且不会先坠落。
4. 确认两名玩家颜色不同、互相可见，移动和水平朝向同步。
5. 双方分别走到第一章舱门与冷却舱两侧，确认地面、墙壁和设备碰撞正常。
6. 使用 F1 隐藏/显示会话面板，F2 检查连接人数，F3 双向发送文字消息。
7. 确认冷却事故温度、任务阶段和敌人不会自行推进；本阶段不应允许维修或战斗。
8. 客户端断开并重连，随后房主停止会话；确认界面恢复可编辑且无残留角色。

## 自动验证

- EditMode：74/74 通过。
- PlayMode：37/37 通过，包含实际启动主机并生成唯一通信预制体的回归测试。
- Windows Development Build：成功。
- 玩家程序启动冒烟：通过。

## 已知边界

- 当前只验证多人进入三舱空间，不验证事故、工具、任务物或敌人同步。
- 第一章之后的舱门仍保持单人流程的初始关闭状态；章节联网推进在 M4-2 实现。
- 当前使用直接 IPv4，不包含 Relay、邀请码或距离语音。

## 已修复问题

- 修复通信组件作为场景内 `NetworkObject` 时因关闭 NGO 场景管理而无法生成的问题；现由主机从已注册预制体生成。
- 联网玩家生成后主菜单会自动绑定本地拥有者，暂停和设置不再依赖场景预置玩家。
- M4 中 `Esc` 只控制暂停菜单；断开操作保留在 F1 会话面板，避免一次输入同时暂停并退出会话。
