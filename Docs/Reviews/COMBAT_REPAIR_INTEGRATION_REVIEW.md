## 本轮验证命题

战斗不取代维修。玩家先处理泄漏，密封完成后出现一次有限干扰；玩家短暂切换冲击扳手保护辅助设备，清除威胁后继续换管、紧固和复位。人工评审应重点判断它更像“维修中的防卫插曲”，还是已经抢走维修主循环的注意力。

## 已实现内容

- 冲击扳手使用 0.38 秒冷却和简单位移挥动；命中干扰体时有闪白、形变、本地短顿帧、轻微镜头震动和程序化占位音；
- 敌人接触设备后先进入明显蓄力，蓄力期间变为警告色并通过跳动连线指向受威胁设备，然后才结算伤害；
- 辅助设备有三段世界空间完整度灯和受损/离线警报，不使用传统敌人或玩家血条；
- 直线干扰体直接接近设备；侧袭附着体先绕到设备一侧，生命更低、移动更快；
- 密封阶段完成后同时激活两名干扰体。设备每次受击都会抬升冷却事故温度，设备离线会统一触发事故失败；
- 地面橙色标记从扳手架引向敌人路线和被保护设备，承担“扳手架 → 敌人 → 设备”的无文字引导；
- 遭遇、敌人和设备均发布只读状态事件，供 M3-2 之后接入主机权威同步；本轮未实现或宣称多人战斗同步。

## 启动方式

### Unity 编辑器

1. 使用 Unity Hub / Unity `6000.0.82f1` 打开工程；
2. 打开 `Assets/Game/Scenes/Combat_CoolingBayIntegration.unity`；
3. 点击 Play。

如需重新生成候选场景，执行 `FunGame > Combat > 生成维修防卫集成场景`。生成器读取 M1 源场景并另存为候选场景，不覆盖源场景。

### Windows 开发构建

运行 `Builds/CombatRepair-Windows/FunGame-CombatRepair.exe`。如需重新构建，执行 `FunGame > Combat > 构建维修防卫 Windows 开发版本`。

## 人工成功路径

1. 从右侧架上取得密封喷枪，完成泄漏点密封；
2. 观察维修目标切换，同时确认两名干扰体开始接近辅助设备；
3. 沿地面标记前往冲击扳手架，换取冲击扳手；
4. 观察敌人攻击蓄力与设备连线，在攻击结算前近距离击退；
5. 清除两名敌人，确认维修目标仍然保留；
6. 继续松开连接、安装替换管件、紧固并在控制台复位。

通过检查：

- [ ] 不阅读说明也能理解敌人正在威胁哪个设备；
- [ ] 攻击蓄力足以让玩家在设备掉完整度前作出反应；
- [ ] 扳手挥动、冷却、闪白、顿帧、轻震和声音共同形成清晰但不过度的命中反馈；
- [ ] 敌人剩余状态可从颜色与形变理解，不需要传统血条；
- [ ] 能从路线和外形区分直线敌人与侧袭附着敌人；
- [ ] 防卫段约 30–60 秒，结束后能自然回到维修，不会误以为关卡已经完成；
- [ ] 控制台对成功、失败和重新开始的提示明确；
- [ ] Console 没有项目代码异常或持续错误。

## 人工失败与重置路径

1. 完成密封并触发干扰后，不处理敌人；
2. 确认设备在每次攻击前都有蓄力与连线提示，受击后温度上升；
3. 等待辅助设备离线，确认冷却事故进入失败状态；
4. 前往冷却控制台按 `E` 重新开始；
5. 确认维修阶段、温度、辅助设备、两名敌人和触发状态全部恢复。
