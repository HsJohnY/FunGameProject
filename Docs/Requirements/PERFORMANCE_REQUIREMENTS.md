# 硬件与性能需求

状态：MVP 性能基线已确认 v0.1；具体硬件需由实际构建复测

## 1. 同类产品参考

以下是 2026-08-31 查询的官方 Steam 页面公开要求，用于确定验证区间，不代表它们实际在所有场景中的帧率：

| 游戏 | 最低 CPU / GPU / 内存 | 推荐 CPU / GPU / 内存 |
| --- | --- | --- |
| [R.E.P.O.](https://store.steampowered.com/app/3241660/REPO/) | Core i5-6600 / GTX 970 / 8 GB | Core i7-8700 / GTX 1070 / 8 GB |
| [PEAK](https://store.steampowered.com/app/3527290/PEAK/) | 2.5 GHz Core i5 / GTX 1060 或 RX 6600 XT / 8 GB | 3.0 GHz Core i5 或 Ryzen 5 / RTX 2060 或 RX 7600 XT / 16 GB |
| [Lethal Company](https://store.steampowered.com/app/1966720/Lethal_Company/) | Core i5-7400 / GTX 1050 / 未列出内存 | 未列出 |
| [RV There Yet?](https://store.steampowered.com/app/3949040/RV_There_Yet/) | Core i7-3820 / GTX 970 / 8 GB | Ryzen 9 3900XT / RTX 3060 / 12 GB |

这些产品的最低 GPU 集中在 GTX 970–1060 级别，最低内存通常为 8 GB；推荐 GPU 跨度较大。我们的目标是可验证的内部基线，不作为商店配置承诺。

## 2. 目标硬件与帧率

### 最低验证目标

- Windows 10/11 64 位；
- Core i5-6600 / i5-7400 同级 CPU；
- GTX 970 / GTX 1060 同级独立显卡；
- 8 GB 系统内存；
- 1080p 低画质，代表性最坏场景不低于稳定 30 FPS；
- 宽带互联网连接。

### 推荐验证目标

- Core i7-8700 或现代 Ryzen 5 同级 CPU；
- GTX 1070 / RTX 2060 同级或更高显卡；
- 16 GB 系统内存；
- 1080p 中画质，代表性场景目标稳定 60 FPS。

- **PERF-TGT-01（已确认，MUST）**：同时验证监听主机和普通客户端；不能只用客户端帧率代表整体性能。
- **PERF-TGT-02（MUST）**：当前不承诺集成显卡支持。若实际好友设备低于最低目标，在灰盒后以真机数据重新评审。
- **PERF-TGT-03（MUST）**：目标是避免持续卡顿和输入不稳定；短暂偶发峰值必须记录来源，不能只报告平均 FPS。

## 3. MVP 中的性能工作

性能不是 MVP 的玩法内容，但可运行性和架构预算属于 MVP 完成条件。

- **PERF-MVP-01（已确认，MUST）**：从首个灰盒开始记录 CPU/GPU 帧时间、内存、GC 分配、网络流量、活跃对象和加载时间。
- **PERF-MVP-02（MUST）**：每个主要里程碑在代表性压力场景中剖析，不以空训练舱或编辑器单一视角作为通过依据。
- **PERF-MVP-03（MUST）**：修复导致目标设备无法游玩、持续掉帧、内存无界增长、频繁 GC 卡顿或网络拥塞的阻塞问题。
- **PERF-MVP-04（SHOULD）**：核心高频循环避免持续的逐帧托管内存分配，并限制无界生成、日志和事件订阅。

MVP 不要求：为未验证瓶颈大规模重写 Job/Burst、定制渲染管线、面向极低端硬件专项适配、复杂无缝流送，或对没有测量证据的代码进行微优化。

## 4. 初始场景与网络护栏

以下为首轮压力场景上限，不是最终玩法承诺：

- 最多 4 名玩家；
- 最多约 8 个同时活跃的小型敌人；
- 最多约 3–4 个可交互故障工作面；
- 最多约 16 个同时活跃的关键网络物理对象；
- 装饰粒子、火花和小碎片只在客户端本地表现；
- 非活跃设备事件驱动，不为每个仪表持续发送高频状态。

- **PERF-BUD-01（MUST）**：超过护栏前必须有玩法理由和剖析结果，不能把上限当作生成目标。
- **PERF-BUD-02（MUST）**：对象池、LOD、遮挡和批处理等优化只在对应瓶颈出现或代表内容需要时引入。
- **PERF-BUD-03（MUST）**：主机权威逻辑、渲染和本地玩家输入必须在同一压力测试中共同运行。

## 5. 画质与渲染边界

- **GFX-01（MUST）**：提供低、中、高三个预设；至少调整阴影、粒子、后处理、视距和渲染比例。
- **GFX-02（MUST）**：不依赖光线追踪、路径追踪、高端全局光照或大量实时阴影灯。
- **GFX-03（MUST）**：第一人称工具、故障、任务物和队友标识在低画质仍清晰。
- **GFX-04（MUST）**：风暴优先通过有限雾、粒子、颜色和声音表达，不依赖大量网络刚体或透明叠层。
- **GFX-05（MUST）**：允许带加载画面的场景切换，MVP 不建设复杂无缝世界流送。

## 6. 加载、内存与构建

- **LOAD-01（SHOULD）**：代表远征首次加载目标不超过 20 秒，最终以最低验证设备实测。
- **LOAD-02（MUST）**：不同时加载三章全部内容；关卡切换验证资源释放和事件解绑。
- **LOAD-03（SHOULD）**：首个 MVP 可分享构建以 5 GB 为软目标、8 GB 为评审门槛；超过时先检查重复和未使用资产。
- **LOAD-04（MUST）**：贴图、音频和模型使用明确导入/压缩预设，重复模块共享材质和资源。

## 7. MVP 设置

MVP 至少提供分辨率/窗口模式、画质预设、垂直同步或帧率上限、鼠标灵敏度、视野范围、镜头晃动强度、动态模糊开关、反转 Y 轴、主音量/音效/通讯音量和字幕大小。

颜色不能是关键状态的唯一表达。专项色觉模式可在初版后评估，但基础形状、文字和声音冗余从 MVP 开始执行。

## 8. 验收场景

代表压力场景同时包含四名玩家替身、计划上限敌人、3–4 个事故工作面、风暴效果、工具反馈、关键任务物、聊天消息和主机权威逻辑。

每次记录构建提交、设备、画质、分辨率、CPU/GPU 帧时间、内存峰值、GC、网络流量、加载时间和异常峰值。未达到目标时先定位真实瓶颈，再决定降级内容、调整预算或优化实现。
