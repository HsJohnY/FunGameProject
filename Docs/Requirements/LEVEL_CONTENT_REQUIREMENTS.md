# 关卡与内容生产需求

状态：需求基线 v1.0；具体章节布局待代表章节试玩

## 1. 总体策略

采用“手工设计关卡骨架 + 数据化故障模块 + 少量受控变化”。主线教学、剧情、章节节奏和高潮由人工确定；运行时不生成完整地图。

- **LVL-01（已确认，MUST）**：主线章节、关键路径、规则教学、剧情节点、精英和 Boss 核心阶段手工设计。
- **LVL-02（已确认，MUST）**：故障、目标和事件使用可注册的数据定义，不把完整规则写死在单个场景脚本中。
- **LVL-03（已确认，MUST）**：MVP 不制作开放世界或完整程序生成地图。
- **LVL-04（MUST）**：受控变化不能改变主线可完成性、首次教学含义或关键任务物是否存在。

## 2. 内容层次

### 手工骨架

人工确定主要区域、可达路线、巨构工作空间、安全站、规则教学、剧情线索和高潮顺序。少量可选停靠点可以提供额外物资或故事，但不建立复杂开放路线网络。

### 语义插槽

场景提供机械故障点、管道破裂点、电力端口、敌人入口、零件安装位、任务物恢复点和玩家安全恢复点。每个插槽声明兼容类型、空间要求、可达性和冲突组。

### 数据化故障模块

故障定义至少包含适用系统、触发条件、症状、恶化阶段、控险动作、所需工具/零件、解决条件、失败影响、人数配置和兼容关系。

- **LVL-MOD-01（MUST）**：模块只能进入兼容且经过验证的语义插槽，不允许任意坐标随机生成关键内容。
- **LVL-MOD-02（MUST）**：模块组合在开局或触发前验证关键路径、资源和最小人数解法。
- **LVL-MOD-03（MUST）**：新增第二个内部内容变体时不修改无关任务或网络核心，以此验证扩展边界。

## 3. 事故计划与受控变化

每个关卡使用人工编写的事故计划控制教学、正常运行、压力升级和高潮。变化只能从当前阶段允许且玩家已经学习的集合中选择。

可以变化：已学故障的合法位置、轻量参数、少量敌人入口、可选物资位置和非关键环境表现。

保持固定：新规则首次教学、主线剧情、关键设备、精英/Boss 核心机制、关键任务零件和完成条件。

- **LVL-VAR-01（MUST）**：所有运行时选择由权威端产生，并记录种子、模块 ID、插槽 ID 和内容版本。
- **LVL-VAR-02（MUST）**：相同种子与内容版本能够复现用于调试的相同选择。
- **LVL-VAR-03（SHOULD）**：近期重复游玩避免连续选择完全相同的非关键变体，但不得为此破坏关卡约束。

## 4. MVP 代表用例

首个用例是一张手工冷却舱灰盒、一条固定冷却故障链，以及两个经过验证的管道破裂插槽。权威端根据记录的种子二选一；剧情、任务零件、敌人干扰和完成条件保持固定。

- **LVL-MVP-01（已确认，MUST）**：只实现一个受控位置变化，不提前建设完整事故导演。
- **LVL-MVP-02（MUST）**：若该变化没有增加可观察价值或显著提高调试成本，允许取消运行时选择，同时保留数据化故障和语义插槽。
- **LVL-MVP-03（MUST）**：核心灰盒目标约 8–12 分钟，多人可玩原型约 15–25 分钟，MVP 代表章节约 30–45 分钟。
- **LVL-MVP-04（已确认，MUST）**：首次通关 4 小时以上仍是完整项目目标，不作为首个 MVP 的内容量门槛。

## 5. 内容制作门禁

- 新规则先在独立安全空间验证，再进入组合事故；
- 代表关卡趣味验证前不批量生产同类场景；
- 正式资产替换灰盒前，交互距离、路线、人数适配和网络状态必须稳定；
- 内容数量不能通过重复低压移动、高频随机故障或仅换皮敌人填充；
- 每个新模块必须说明复用场景、独立玩法价值和测试方法。

## 6. 验收

- 两个破裂位置使用同一故障定义且无需复制规则代码；
- 2–4 人在两个位置都有可完成路径；
- 相同种子可复现相同选择，所有客户端显示一致；
- 首次教学和剧情不会因变化错序；
- 删除运行时随机选择后，固定关卡仍然完整可玩；
- 关卡作者可以从插槽或模块定义定位组合失败原因。
