# Game Brief

状态：讨论稿 v0.1

## 当前产品定义

一款面向 2–4 名朋友的 3D 合作远征游戏。玩家组成维修队，共同维护一座穿越灾变区域的移动基地；团队需要诊断连锁故障、搬运和安装零件、执行舱外维修，并在持续前进的压力下决定系统优先级与冒险停靠计划。

## 已确认方向

- 3D 游戏。
- 合作远征是主要内容。
- 包含游戏内成长系统。
- 包含玩家协作解决的问题或谜题。
- 项目结构应清晰、易维护和便于未来扩展。
- 不以完整第三方 Mod 平台作为近期目标。
- 美术采用类似 PEAK、How to Fish 的低复杂度风格化方向，不追求高精度写实资产。
- 核心概念采用“移动基地维修队”。
- 核心劳动包括诊断、拆装、搬运、连接、校准与临时修复。
- 主背景采用受周期性超级风暴影响的荒原，玩家维护持续迁徙的陆行移动城镇。

## 建议基线

- Windows PC 首发，Steam 作为首选分发与好友联机平台。
- 2–4 人好友房；首个网络原型先验证 2 人。
- 单局目标 15–30 分钟。
- 局内成长以临时工具和路线选择为主，局外成长以横向解锁为主。
- 失败有成本，但尽量允许队友补救，避免长时间旁观。
- 用一个核心交互工具贯穿工作、解谜、互救和有限胡闹。

## 尚未决定

- 陆行移动基地采用履带、多足或混合结构。
- 第一人称或第三人称。
- 战斗在体验中的占比，甚至是否存在传统战斗。
- 网络框架、主机模式与后续专用服务器需求。
- 程序化生成的具体范围。
- 成长是否跨局、哪些内容永久保留。

## 已确认体验支柱

1. **合作让移动基地继续前进**：信息互补、临时分工与空间协作决定维修结果，每名玩家都有贡献空间。
2. **可理解的连锁危机与临场取舍**：故障有原因、征兆和后果，团队必须决定先修什么、牺牲什么以及是否冒险。
3. **把漂泊机器逐渐变成共同家园**：航程和章节成果会在移动基地的功能、空间、外观或生活中留下可见变化。

## 当前明确不做

- 大型开放世界或 MMO。
- 竞技排位与强 PvP 平衡。
- 大量互不相关的小游戏合集。
- AAA 写实角色与环境制作标准。
- 在核心玩法未验证前开发完整 Mod SDK、Workshop 或代码脚本平台。
- 在原型阶段制作大量正式关卡、剧情和永久成长内容。
