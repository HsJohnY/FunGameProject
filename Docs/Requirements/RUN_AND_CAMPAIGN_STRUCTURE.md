# 单局与主线结构

状态：第三部分讨论稿 v0.1

## 1. 已确认方向

- 一局代表巨构从当前安全站前往下一安全站的一段航程。
- 单局基础目标是让巨构保持运行并抵达终点。
- 关卡驱动力由明确航程目标与剧情使命共同提供。
- 游戏不应高频迫使玩家永久放弃系统、队友或关键成果。
- 主任务完成后应立即推进，不使用固定等待时间或无限刷怪填充航程。
- 低压阶段用于教学和节奏调节，随主线推进逐渐缩短。
- 首次完成主线的目标游戏寿命不少于 4 小时。
- 主线需要提供明确使命，并让玩家逐步揭开一个持续发展的谜团。

## 2. 决策强度原则

维修游戏仍需要优先级和临场判断，否则会退化成按顺序完成清单。但决策重点调整为“如何完整解决”，而不是频繁选择“必须放弃什么”。

### 主要保留

- 维修顺序；
- 玩家分工；
- 使用正式维修或临时旁路；
- 选择更安全或更高效的执行方案；
- 是否承担少量、明确的可选目标。

### 限制使用

- 不可逆地牺牲关键系统；
- 强迫遗弃队友；
- 高频二选一永久奖励；
- 玩家未获得充分信息时的重大损失选择；
- 用资源不足强制制造“无论如何都救不全”的局面。

熟练、沟通良好的队伍原则上应有机会完整处理主要问题。失败更多来自执行、判断和故障恶化，而不是设计预先规定的必然损失。

## 3. 单局阶段

目标时长暂定 20–25 分钟，后续由试玩数据调整。

### 阶段 A：安全站整备

玩家了解航程目标、主要环境风险和剧情背景，检查巨构状态并选择有限工具与备件。整备应简洁，避免复杂经营菜单。

### 阶段 B：航程进入

早期关卡提供低压空间，让玩家理解新系统、地貌或工具；后期关卡只保留必要的方向建立和短暂喘息。

### 阶段 C：正常运行与基础故障

出现征兆清晰的单系统问题、搬运、舱外维修和基础协作。少量小型敌人可以干扰维修，空闲玩家负责防卫或准备后续工作。

### 阶段 D：故障关联与环境升级

环境压力与机器状态开始关联。队伍处理维修顺序、并行任务和临时方案，但主路径不要求必然放弃关键成果。

### 阶段 E：终点挑战

抵达安全站前出现集中挑战，综合使用本局已经教授的系统。普通航程规模较小，章节结尾升级为包含精英敌人的多阶段工程灾难关。

## 3A. 防止无贡献等待

- 主任务完成后立即触发下一阶段、开放终点或允许队伍确认继续。
- 长维修任务必须提供搬运、控制、诊断、防卫或准备等并行贡献路径。
- 只能由一名玩家完成的交互应保持短促。
- 短暂喘息必须承担整理、叙事、预告或环境观察功能。
- 战斗只作为有限干扰，不以无限波次替代流程推进。

### 阶段 F：结算与剧情推进

展示航程完成、巨构状态、额外成果、损伤与成长，并通过任务结果、无线电、环境证据或基地变化推进主线谜团。

## 4. 低压阶段递减

低压不等于无事件。它应承担教学、预告、角色交流或环境叙事功能。

建议节奏：

| 进度 | 低压阶段目标 | 建议长度 |
| --- | --- | --- |
| 序章/首航 | 教授移动、交互、基础维修与救援 | 4–6 分钟 |
| 第一章普通航程 | 引入一个新系统并允许试用 | 2–3 分钟 |
| 中期航程 | 快速建立路线和异常征兆 | 1–2 分钟 |
| 后期/灾难关 | 直接从已知压力或事件开始 | 0–1 分钟 |

安全站承担主要休息和整理功能，避免在每局内部重复长时间无压力航行。

## 5. 成功与失败基线

### 成功

巨构抵达下一安全站。机器状态、维修质量和额外任务影响奖励与后续表现，但不会否定已经完成的航程。

### 个人倒地

个人倒地不立即导致整局失败。队友应有救援窗口；具体恢复方式与代价待失败系统阶段确认。

### 整队失败候选

当前建议：巨构失去推进能力，并在明确抢修窗口内未恢复，最终被风暴追上。失败返回上一个安全站，失去本局大部分临时成果，但不清空长期主线进度。

该失败规则尚未冻结，需要与剧情、存档和章节回退共同评审。

## 6. 主线寿命与内容预算

### 已确认目标

首次主线通关目标不少于 4 小时。该时长不包括重复失败、自由重玩或未来内容。

### 当前建议范围

- 3 个正式章节；
- 每章 3 段普通航程；
- 每章 1 个工程灾难关；
- 序章和最终结局段；
- 合计约 12–14 个主要任务节点；
- 单局 20–25 分钟，首次通关预计约 5–7 小时。

这只是内容规划候选，不是 MVP 承诺。必须通过模块复用、故障组合和环境变化控制制作量，避免用大量一次性关卡堆时长。

## 7. 剧情驱动要求

### 已确认

- 玩家从游戏早期就知道自己承担一项重要使命，而不是无目的地往返安全站。
- 每个章节必须推进任务或改变玩家对世界谜团的理解。
- 章节工程灾难关同时承担玩法高潮和剧情转折。
- 最终章节需要对主要使命提供明确结果，并回答核心谜团的主要问题。

### 建议表达方式

- 简短任务简报与无线电通信；
- 荒原设施、遗迹和失事载具中的环境线索；
- 巨构新增成员、舱室、设备和可见损伤；
- 维修记录、航行日志和回收物；
- 少量关键演出，而非大量高成本过场和面部动画。

### 尚未决定

- 风暴的具体来源和真相；
- 三座稳定站各自的章节事件与线索；
- 主要叙事角色；
- 剧情是完全线性，还是允许少量路线顺序变化；
- 配音范围。

已确认的主线使命、校准核心和稳定站框架见 `NARRATIVE_REQUIREMENTS.md`。

## 8. 第三部分剩余决策

1. 单局主任务是否始终是抵达安全站，还是允许少量不同任务形态；
2. 普通航程中保留多少可选目标；
3. 推进失效是否作为唯一整队失败条件；
4. 三章、12–14 个任务节点是否符合最终制作范围；
5. 三章剧情节拍与核心谜团的唯一答案；
6. 结算如何连接成长和下一段航程。
