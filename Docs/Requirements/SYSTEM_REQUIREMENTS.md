# 功能系统需求

状态：讨论稿 v0.1

## 1. 玩家与交互

- **SYS-PLY-01（MUST）**：3D 角色移动必须在目标视角下提供稳定、可预测的地面移动与基础环境交互。
- **SYS-PLY-02（已确认，MUST）**：采用固定第一人称，不同时维护第三人称操作模式。
- **SYS-PLY-03（MUST）**：交互目标必须通过距离、轮廓、提示或动画清晰反馈可用性与失败原因。
- **SYS-PLY-04（MUST）**：输入动作应保持精简，并支持后续键位重绑定。
- **SYS-PLY-04A（已确认，MUST）**：查看、拾取、携带、放置、插入和设备操作等互斥行为优先复用统一上下文交互；执行前必须预览动作并使用稳定优先级。
- **SYS-PLY-05（SHOULD）**：角色外观能区分队友，并在低光、遮挡和远距离下保持轮廓可读。

## 2. 工具与物品

- **SYS-ITEM-01（MUST）**：物品使用稳定、带命名空间的 ID，静态定义与运行时实例分离。
- **SYS-ITEM-02（MUST）**：拾取、持有、使用、丢弃和网络所有权转换具有明确规则。
- **SYS-ITEM-03（MUST）**：任务关键物品不得因穿透、掉出地图或断线永久阻塞关卡。
- **SYS-ITEM-04（SHOULD）**：工具能力通过组合接口表达，避免为每件物品复制完整交互代码。
- **SYS-ITEM-05（已确认，MUST）**：MVP 核心工具收敛为冲击扳手、密封喷枪和线路桥接器，工具可重复携带且不绑定职业。详细规则见 `TOOLS_AND_ITEMS_REQUIREMENTS.md`。
- **SYS-ITEM-06（MUST）**：主线按两人可完成设计；未携带正确工具时提供低效应急旁路，不因人数或配装硬锁。
- **SYS-ITEM-07（已确认，MUST）**：每名玩家携带一件主工具和一个可见手持物；无格子背包，手持大型物品时不能使用工具或冲刺。
- **SYS-ITEM-08（已确认，MUST）**：核心工具无永久耐久、弹药或独立电池，只使用自动恢复的短时动作限制。
- **SYS-ITEM-09（已确认，MUST）**：资源收敛为一种团队共享维护物资；任务零件实体搬运，MVP 只要求一种支援物品。
- **SYS-ITEM-10（MUST）**：资源不足降低效率和容错，但不得永久阻塞主线。

## 3. 任务与远征

- **SYS-MIS-01（MUST）**：任务定义包含目标、区域、风险条件、成功、失败、奖励和可选目标。
- **SYS-MIS-02（MUST）**：任务状态由权威端推进，并能为所有玩家提供一致、可读反馈。
- **SYS-MIS-03（SHOULD）**：任务由可组合目标和事件构成，但 MVP 不承诺完全程序化生成。
- **SYS-MIS-04（MUST）**：关卡具备开始、结算、重新开始和异常恢复路径。
- **SYS-MIS-05（已确认，MUST）**：MVP 完整实现常规穿越任务；节点维修与救援/回收使用同一任务框架，但分别延后到可玩原型和垂直切片评估。

## 4. 环境、事件与谜题

- **SYS-ENV-01（MUST）**：环境模块应有明确输入、输出和复位规则，可在不同场景复用。
- **SYS-ENV-02（MUST）**：谜题逻辑不依赖场景对象名称或隐式查找。
- **SYS-ENV-03（SHOULD）**：事件由条件、效果、持续时间、优先级和可见提示定义。
- **SYS-ENV-04（SHOULD）**：危险对玩家、工具与任务物的影响采用统一规则，减少例外。
- **SYS-ENV-05（LATER）**：支持由种子控制的内容布局，便于复现网络与关卡问题。

## 5. 状态、伤害与救援

- **SYS-STATE-01（MUST）**：玩家状态变化具有来源、强度、持续时间和清除条件。
- **SYS-STATE-02（MUST）**：倒地、救援和彻底退出远征是不同状态，不混用销毁角色对象表达。
- **SYS-STATE-03（SHOULD）**：负面状态优先改变决策与协作需求，而不是只降低移动速度或生命值。
- **SYS-STATE-04（已确认，MUST）**：MVP 只实现一个基础状态值以及正常、危险、倒地；不实现个人 Buff、部位伤势或复杂异常系统。详细规则见 `PLAYER_STATE_AND_RESCUE.md`。
- **SYS-STATE-05（已确认，MUST）**：倒地玩家可爬行、观察、沟通和标记；队友可拖离并现场扶起，不存在个人永久死亡和长时间观战。
- **SYS-COMBAT-01（已确认，MUST）**：包含有限战斗，使用维修工具防卫、小型干扰敌人、章节精英和最终 Boss；不建立独立传统枪械主循环。详细边界见 `COMBAT_REQUIREMENTS.md`。

## 6. 成长、经济与存档

- **SYS-PROG-01（MUST）**：结算将局内结果转换为清晰的局外记录或解锁。
- **SYS-PROG-01A（已确认，MUST）**：失败保留剧情知识和既有永久进度，失去本局临时升级、大部分临时资源与未带回的任务物；连续失败不得形成不可恢复的死亡螺旋。
- **SYS-PROG-02（MUST）**：局外进度具有 Schema 版本，能检测不兼容或损坏数据。
- **SYS-PROG-03（SHOULD）**：成长内容以可注册定义表达，新增解锁不需要修改旧存档结构。
- **SYS-PROG-04（MUST）**：存档写入使用安全替换或备份机制，避免中断造成唯一存档损坏。
- **SYS-PROG-05（已确认，MUST）**：MVP 不加入成长货币、个人经验或随机装备；已确认的失败损失按 `RUN_AND_CAMPAIGN_STRUCTURE.md` 执行。
- **SYS-PROG-06（已确认，MUST）**：MVP 只实现一个局内共享模块和一个局外巨构升级；不实现个人等级、技能树、个人属性或多货币经济。详细规则见 `PROGRESSION_REQUIREMENTS.md`。
- **SYS-PROG-07（已确认，LATER）**：个人成长保留为后续候选；当前仅要求稳定玩家 ID、版本化存档和可组合效果边界，不建设空置的完整成长框架。

## 7. 房间与社交

- **SYS-LOB-01（MUST）**：创建房间、邀请、加入、准备、开始、离开和返回大厅具有明确状态。
- **SYS-LOB-02（MUST）**：显示玩家连接、准备、加载和断线状态。
- **SYS-LOB-03（SHOULD）**：房主能选择任务和基础规则，但不提供复杂服务器管理面板。
- **SYS-LOB-04（LATER）**：公开房间、快速匹配、踢人、封禁和举报。
- **SYS-VOICE-01（LATER/待决策）**：内置距离语音；前期可依赖外部语音完成趣味验证。

## 8. UI、音频和反馈

- **SYS-UI-01（MUST）**：HUD 只展示当前决策需要的信息，避免长期覆盖大量数值。
- **SYS-UI-02（MUST）**：任务、交互失败、风险升级、队友求救和结算具有不同反馈层级。
- **SYS-UI-03（SHOULD）**：颜色不是表达关键状态的唯一手段。
- **SYS-AUD-01（MUST）**：危险、任务物、工具状态与队友关键行为具有空间化或易辨识音频反馈。
- **SYS-AUD-02（SHOULD）**：音频可帮助玩家在视线外获取有限信息，但不替代所有视觉提示。

## 9. 内容扩展边界

- **SYS-EXT-01（MUST）**：任务、物品、事件和环境模块通过注册表或目录清单加载，避免散落的全局查找。
- **SYS-EXT-02（MUST）**：核心运行时代码不直接依赖具体内容包。
- **SYS-EXT-03（SHOULD）**：制作第二份内部内容包时不修改无关核心模块，以此验证可扩展性。
- **SYS-EXT-04（LATER）**：第三方 Mod 加载、Workshop、依赖解析、代码脚本与公开 API。
