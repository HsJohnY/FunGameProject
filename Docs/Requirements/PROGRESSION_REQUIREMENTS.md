# 成长系统需求

状态：需求基线 v1.0；个人成长保留为后续候选

## 1. 设计目标

成长应加强合作远征、章节驱动力和巨构逐渐恢复的成就感，不以永久数值替代玩家对故障规则、工具和协作的学习。MVP 只验证一项局内临时成长和一项局外永久成长的完整链路。

- **PROG-01（已确认，MUST）**：MVP 成长以队伍共享和共同巨构为对象，不实现个人等级、技能树或个人数值升级。
- **PROG-02（已确认，MUST）**：个人等级、技能树和个人升级保留为后续候选，不标记为永久排除。
- **PROG-03（MUST）**：保留可能性不等于提前制作完整框架；MVP 只建立当前用例需要的稳定玩家 ID、版本化存档和可组合效果边界。
- **PROG-04（MUST）**：是否加入个人成长必须在首个可玩版本后，根据留存动机、好友差距和核心玩法测试重新评审。

## 2. 局内成长代表用例

MVP 只实现一个团队共享的“应急旁路模块”：

- 在航程中通过探索或可选工作取得；
- 安装到巨构的一个系统插槽；
- 在一次严重故障中暂时停止该系统继续恶化；
- 只争取维修时间，不自动完成维修；
- 本局结算时移除。

- **PROG-RUN-01（已确认，MUST）**：实现获得、携带/登记、安装、生效、消耗或失效、结算清除和网络同步的完整链路。
- **PROG-RUN-02（MUST）**：模块效果改变系统状态或操作关系，不向个人提供简单维修速度、伤害或生命加成。
- **PROG-RUN-03（MUST）**：MVP 不制作第二个局内模块，除非第一个用例无法验证扩展边界或试玩证明存在阻塞。

## 3. 局外成长代表用例

MVP 只实现一个永久的“故障预警中继”：

- 完成第一个气象稳定站后恢复；
- 在重大故障发生前提示受影响系统和大致区域；
- 不直接显示根因或完整解决步骤；
- 通过巨构新增天线、控制台、灯光或声音留下可见成果；
- 对使用该战役存档的全队生效。

- **PROG-META-01（已确认，MUST）**：永久成长由章节或使命里程碑解锁，不要求重复刷取经验或货币。
- **PROG-META-02（MUST）**：失败不撤销已经获得的永久升级。
- **PROG-META-03（MUST）**：新加入的朋友立即共享战役设施和基础能力，不需要补刷个人等级。
- **PROG-META-04（MUST）**：预警只改善准备和信息可读性，不替代诊断与协作。

## 4. 存档归属

- **PROG-SAVE-01（MUST）**：战役章节、巨构设施和已恢复航线属于战役存档，不绑定单一角色战力。
- **PROG-SAVE-02（MUST）**：玩家记录使用稳定身份，但 MVP 只保存设置、外观占位和必要参与记录，不写入未实现的等级或技能数据。
- **PROG-SAVE-03（MUST）**：成长存档包含 Schema 版本并支持缺失字段默认值，使后续新增个人成长时可以迁移，而不需要现在预留空技能树。

## 5. MVP 明确不做与后续候选

MVP 不实现：个人经验等级、技能树、永久个人属性、多个成长货币、随机装备词条、模块品质、模块合成、每日任务和重复刷取循环。

后续可评审：个人专精、技能树、角色长期升级和更多共享模块。加入条件包括核心玩法已经成立、不会让新玩家失去贡献空间、能提供新的操作或协作选择，并具有与复杂度相称的试玩证据。

## 6. 验收

- 玩家能理解局内模块为何只在本次航程生效；
- 应急旁路产生一次有意义的团队使用时机，但不代替维修；
- 故障预警中继在功能和巨构外观上留下可见变化；
- 新玩家加入已有进度的战役时具有完整基础能力；
- 存档可以在缺少未来个人成长字段时正常加载和升级；
- 删除所有未实现的个人成长占位内容后，MVP 仍能完整运行。
