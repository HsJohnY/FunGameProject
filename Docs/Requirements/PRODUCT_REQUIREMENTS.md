# 产品需求

状态：讨论稿 v0.1

## 1. 产品目标

### PR-01（已确认，MUST）

产品必须以多人合作远征为主要体验，而不是将联机作为单机玩法的附加模式。

### PR-02（建议，MUST）

产品必须提供一句话可解释的核心劳动、明确的共同目标和持续升级的局内压力。

### PR-03（建议，MUST）

每局应自然产生可被玩家复述的合作、事故、救援或临场应对故事。

### PR-04（已确认，MUST）

产品采用 3D 表现，画面目标是低复杂度、风格化、轮廓清晰，而非写实高精度。

### PR-05（已确认，MUST）

工程结构必须支持开发团队持续加入任务、物品、事件、环境模块和谜题，而不需要反复重写核心系统。

### PR-06（已确认，MUST）

首次完成主线的目标游戏寿命不少于 4 小时，并具有明确使命、章节进展和能够获得主要答案的核心谜团。

## 2. 目标玩家

### PR-AUD-01（建议）

主要玩家是拥有 1–3 名固定朋友、希望获得轻压力合作与搞笑事故，而非高强度竞技的 PC 玩家。

### PR-AUD-02（建议）

玩家应能在约 5 分钟内理解基本操作和单局目标，在第一局中完成一次有意义的协作。

### PR-AUD-03（待决策）

是否要求完整单人体验。当前建议只保证开发测试可单人运行，不承诺单人也具有与多人相同的乐趣和平衡。

## 3. 平台与项目边界

### PR-PLAT-01（建议，MUST）

首个目标平台为 Windows 10/11 64 位 PC，键鼠为首要输入。

### PR-PLAT-02（建议，SHOULD）

控制器支持应在 MVP 前验证，但不应阻塞最早期灰盒原型。

### PR-PLAT-03（已确认，MUST）

项目用于个人练习和好友联机，通过可分享的 Windows 构建交付；当前不接入 Steamworks，不以商店发布为需求。

### PR-BIZ-01（已确认）

定价、商店页、抢先体验、商业 Demo、成就和长期运营明确不进入当前项目范围。若未来改变目标，需要重新评审联网、合规、质量和发布需求。

## 4. 体验原则

### PR-EXP-01（MUST）

队友必须能够改变玩家可获得的信息、可使用的路径、可承受的风险或可执行的操作。

### PR-EXP-02（MUST）

系统性意外必须具有可读因果。玩家可以没预料到结果，但应能理解发生原因。

### PR-EXP-03（MUST）

失败应具有成本，同时在多数情况下保留补救窗口；死亡或淘汰不得默认造成长时间无参与。

### PR-EXP-04（SHOULD）

熟练玩家应通过知识、沟通、路线和工具使用提高表现，而不只依靠永久属性。

### PR-EXP-05（SHOULD）

玩家之间允许有限、可恢复的胡闹行为，但不得让单人轻易永久毁掉整局。

### PR-EXP-06（已确认，MUST）

不同人数的主线体验必须完整。专业分工可以改变解决方案和效率，但不得让两人队伍因缺少固定职业无法推进。

### PR-EXP-07（已确认，MUST）

产品必须具有即时、单局、章节和长期四个层级的目标与成就反馈。

## 5. 产品成功标准

- 未阅读文档的测试玩家能在 5 分钟内说出当前任务。
- 测试玩家能指出至少一次“必须或明显值得与队友配合”的时刻。
- 一局结束后，玩家能复述至少一个由系统与玩家共同产生的事件。
- 玩家愿意在理解失败原因后立即再尝试一次。
- 新内容可以通过既定注册和配置方式加入，而不修改无关模块。
- 2–4 人典型网络环境下，核心交互不会因延迟失去可理解性。

## 6. 范围约束

- 先证明一项核心劳动，不同时制作多套职业或小游戏。
- 先完成一个代表性远征切片，不以关卡数量证明完成度。
- 先验证好友房，不承诺公开匹配、跨平台或专用服务器。
- 先建立内部扩展路径，不公开第三方 Mod 承诺。
- 需求讨论中的举例不自动进入 MVP；开发前必须将候选方案收敛为明确需求或原型假设。
