# 世界主题：风暴荒原移动城镇

状态：需求基线 v1.0

## 主题摘要

世界受到周期性超级风暴影响，固定聚落难以长期生存。玩家所属的群体生活在一座持续迁徙的陆行巨构上，依靠它穿过荒原、连接安全区并完成关键任务。维修队负责让这座老旧、不断改造的移动城镇继续前进。

## 已确认内容

- 主背景采用风暴荒原。
- 核心载具是陆行巨构，而非固定基地、普通汽车、列车或空中载具。
- 巨构需要持续前进，风暴与环境窗口为航程提供外部压力。
- 巨构既是任务对象，也是玩家共同家园和长期成长的可见载体。
- 整体情绪采用“紧张但温暖的荒诞维修冒险”。
- 采用易理解、低复杂度的风格化 3D 表现。

## 已确认的补充边界

- 风暴与失准的旧气象网络有关，但不会在结局被彻底消灭；
- 巨构采用模块化多履带陆行工程平台；
- 主线终点是中央气象网络区域；
- MVP 只需要一种干扰维修的小型非人类敌对目标，不加入敌对人类阵营；
- 文明组织、年代名称和更多社会细节仅在任务文本需要时补充，不建立独立设定系统；
- 色彩和形状基线见 `CONTENT_AND_ART.md`。

## 为什么选择该主题

- 玩家能直观理解“风暴追赶 → 机器必须前进 → 故障必须维修”的因果链。
- 机械、燃料、冷却、防风、通讯与路线可以自然形成维修系统。
- 履带、舱室、管线和工业零件适合模块化低模制作。
- 首个原型可在静止舱段内用背景运动和环境反馈模拟行驶，不必立即实现完整移动平台。
- 荒原能够容纳多种地貌与灾害，而不必更换核心游戏结构。

## 视觉方向基线

- 外部荒原尺度大、危险、颜色受天气主导；内部舱室拥挤、生活化并具有玩家维护痕迹。
- 巨构应显得经过长期拼装和修补，而非全新、整洁的科幻设备。
- 重要系统使用明确的形状、颜色和运动状态，玩家无需阅读大量文字即可判断大致功能。
- 故障通过声音、灯光、泄漏、振动、温度和机械运动表达，不只显示 UI 图标。
- 视觉风格可以夸张和幽默，但功能关系必须可读。

## 环境内容方向

完整项目地貌内容池包括：

- 开阔沙尘荒原；
- 废弃工业带；
- 岩石峡谷与狭窄通道；
- 雷暴平原；
- 巨型机械残骸区；
- 临时安全站和补给聚落。

这些名称不是 MVP 内容承诺。MVP 只实现冷却舱和一种风暴荒原外部表现；后续地貌必须通过内容预算门禁逐一批准。

## 备选主题储备

以下方案保留为未来概念稿，不属于当前 MVP 或已承诺章节：

### 冰封区域

可作为陆行巨构进入极寒带后的大型区域，重点变化为热循环、冻结、除冰和视野。它与现有载具复用度最高，最适合未来优先评估。

### 云海区域

原“移动空港”方案不直接并入主游戏，因为它会将陆行巨构改成飞行平台并引入全套飞行同步。未来若使用，应改写为高原、浮空异常或临时悬浮模块，保持核心载具和维修语汇一致。

### 生物机械区域

原“生物机械方舟”不直接替换主巨构。未来可将其转化为荒原中的感染区域、共生模块或古代生物机械遗迹，以有限方式引入有机维修规则。

## 未来主题准入规则

任何大型新区域必须：

- 继续服务同一座陆行巨构和核心维修劳动；
- 复用大部分移动、交互、任务和网络规则；
- 只引入少量可解释的新环境变量；
- 不要求为了一个章节重做玩家控制、载具拓扑或核心同步模型；
- 在主游戏 MVP 完成后重新评估，而不是提前预留复杂实现。
