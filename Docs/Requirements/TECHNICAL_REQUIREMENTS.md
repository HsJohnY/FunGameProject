# 技术与非功能需求

状态：讨论稿 v0.1

## 1. 联机模型

- **NET-01（MUST）**：核心玩法按 2–4 人设计，首个网络切片至少验证两个真实进程。
- **NET-02（建议）**：关键任务、奖励、状态和任务物由主机/权威端判定，客户端不得自行确认关键结果。
- **NET-03（MUST）**：视觉表现与权威状态分离，允许客户端插值、预测或本地反馈而不改变规则真相。
- **NET-04（MUST）**：定义每种网络对象的生成者、所有者、可写字段、销毁和断线转移规则。
- **NET-05（MUST）**：不依赖逐帧同步全部物理世界；只同步对玩法必要的状态。
- **NET-06（待决策）**：监听主机、Relay、Dedicated Server 或混合拓扑。MVP 建议从好友房监听主机开始，但需在框架评估后确认。
- **NET-07（待决策）**：中途加入。当前建议原型不支持，MVP 至少支持大厅加入；远征中加入需单独评估状态快照成本。
- **NET-08（SHOULD）**：短暂断线可在限定时间内重连，并恢复玩家身份与必要状态。
- **NET-09（MUST）**：版本或内容清单不一致时阻止开局，并给出可理解原因。
- **NET-10（MUST）**：网络测试至少覆盖延迟、抖动、丢包、客户端退出和主机退出。
- **NET-11（待决策）**：主机迁移。默认不纳入第一个 MVP，必须提供明确的主机退出结果。

## 2. 性能目标

- **NFR-PERF-01（建议）**：目标设备在 1080p、合理画质下维持 60 FPS；最低可接受 30 FPS 需在硬件基线确定后细化。
- **NFR-PERF-02（MUST）**：性能预算至少拆分 CPU、GPU、内存、网络带宽和加载时间。
- **NFR-PERF-03（SHOULD）**：代表性远征首次加载目标不超过 20 秒，场景内避免不可解释的长卡顿。
- **NFR-PERF-04（MUST）**：禁止无界生成对象、日志、事件订阅或网络消息。

## 3. 可靠性与诊断

- **NFR-REL-01（MUST）**：正式构建中无持续 Console 错误和未处理异常。
- **NFR-REL-02（MUST）**：关键状态转换记录结构化日志，包含会话、玩家、任务和对象标识，但不记录敏感凭据。
- **NFR-REL-03（SHOULD）**：严重错误能生成足以复现的版本、场景、种子和网络上下文。
- **NFR-REL-04（MUST）**：所有持久数据写入失败均可检测并向玩家提示。

## 4. 可维护性

- **NFR-MNT-01（MUST）**：运行时、编辑器、测试和第三方代码使用独立程序集边界。
- **NFR-MNT-02（MUST）**：普通 C# 规则与 Unity 生命周期适配分离；MonoBehaviour 不作为所有业务状态的默认容器。
- **NFR-MNT-03（MUST）**：静态配置与每局运行状态分离，不在 ScriptableObject 资产中保存局内可变状态。
- **NFR-MNT-04（MUST）**：禁止将全局可变单例作为默认模块通信方式。
- **NFR-MNT-05（SHOULD）**：公共接口与序列化数据变更需要迁移说明或 ADR。
- **NFR-MNT-06（MUST）**：第三方包放入独立边界，通过适配层接入关键系统。

## 5. 测试要求

- **NFR-TST-01（MUST）**：纯规则、状态机、成长结算和数据验证使用 EditMode 测试。
- **NFR-TST-02（MUST）**：角色交互、场景任务和网络生命周期使用 PlayMode/多人测试。
- **NFR-TST-03（MUST）**：每个里程碑包含可执行手工试玩清单与观察记录。
- **NFR-TST-04（SHOULD）**：关键缺陷修复附带回归测试或明确说明无法自动化的原因。

## 6. 构建与版本

- **NFR-BLD-01（MUST）**：开发、测试和发布构建使用可重复配置，版本号与 Git 提交可追踪。
- **NFR-BLD-02（MUST）**：里程碑推送 GitHub、创建带注释标签并生成外部 Git bundle。
- **NFR-BLD-03（SHOULD）**：建立命令行构建与测试入口，后续接入 CI。
- **NFR-BLD-04（MUST）**：密钥、令牌、平台凭据和本地用户配置不得提交版本库。

## 7. 安全与玩家治理

- **NFR-SEC-01（MUST）**：客户端输入和内容 ID在权威端验证范围与合法性。
- **NFR-SEC-02（MUST）**：网络反序列化不得实例化任意类型或执行任意脚本。
- **NFR-SEC-03（LATER）**：公开匹配上线前补齐屏蔽、举报、踢出、封禁和行为准则。
- **NFR-SEC-04（LATER）**：若开放第三方内容，必须先定义信任、权限、沙箱和崩溃归因模型。

## 8. 暂缓技术决策

以下内容必须通过需求和网络原型后再选型：Unity 网络框架、Steamworks 封装、语音服务、Relay、物理同步方案、依赖注入框架、Addressables 使用范围和存档格式。不得只因流行而引入。
